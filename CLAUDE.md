## Что это

Ementium — agent-приложение для macOS (`LSUIElement`), подменяющее Quick Look для изображений: Пробел в Finder открывает выделенную картинку полноэкранным оверлеем, стрелки листают изображения каталога, Esc закрывает. Нет Dock-иконки, нет меню; единственный UI — окно настроек. Процесс работает постоянно: Esc закрывает только окно просмотра, выход — через настройки или menu bar.

## Сборка

Полного Xcode в системе нет — установлены только Command Line Tools (`xcode-select -p` → `/Library/Developer/CommandLineTools`), поэтому `xcodebuild` недоступен. Доступен `swift` 6.4. Прежде чем предлагать команды сборки, уточни у пользователя целевой формат проекта: Xcode-проект (как в README), SwiftPM-пакет или XcodeGen/Tuist-генерация. Это первое архитектурное решение, которое нужно принять, а не угадать.

Что бы ни выбрали — цель должна собираться как Universal binary (arm64 + x86_64), с выключенным App Sandbox и включённым Hardened Runtime + Apple Events.

## Архитектура: ключевые ограничения

Эти вещи определяют устройство кода и не выводятся из отдельных файлов.

**CGEventTap должен отвечать мгновенно.** Решение «поглотить Пробел или пропустить» принимается синхронно в callback. Любая блокирующая работа внутри — и система отключит tap с `kCGEventTapDisabledByTimeout`. Поэтому: получение выделения Finder через Apple Events (медленное, десятки мс) нельзя делать в callback, а tap нужно уметь переподключать после отключения.

**Отсюда главная нерешённая проблема:** чтобы не ломать Quick Look для PDF и видео, нужно знать тип файла до решения о поглощении — но тип приходит асинхронно. Три варианта в README («Открытые вопросы»): своя `QLPreviewPanel` для не-изображений, быстрое чтение выделения через Accessibility API в callback, или ресинтез Пробела обратно в Finder. Выбор не сделан — не реализуй молча один из них.

**Никакого App Sandbox и никакого Mac App Store.** `CGEventTap` и управление Finder через Apple Events несовместимы с песочницей. Распространение только через Developer ID + нотаризацию (`notarytool`).

**Разрешения привязаны к подписи.** Нужны Accessibility (`AXIsProcessTrustedWithOptions`), возможно Input Monitoring (`CGPreflightListenEventAccess`), и Automation → Finder (`NSAppleEventsUsageDescription`). При разработке подпись меняется, и macOS «забывает» выданный доступ — приложение придётся удалять из списка в Системных настройках и выдавать доступ заново. Учитывай это при отладке: «не работает перехват» чаще означает слетевшее разрешение, а не баг в коде.

**Декодирование — через thumbnail, не через загрузку оригинала.** `CGImageSourceCreateThumbnailAtIndex` с ограничением по размеру экрана и `kCGImageSourceCreateThumbnailWithTransform` для EXIF-ориентации. Иначе RAW и большие фото съедят память. Кэш держит окно ±N вокруг текущего изображения.

**AppKit для оверлея, SwiftUI для настроек.** Окну просмотра нужен точный контроль уровня окна, фокуса и обработки клавиш — на SwiftUI это не делается. Настройки — `Settings` scene + `@AppStorage`.

**Тип файла — только через `UTType` (`conforms(to: .image)`)**, никогда по расширению. Сортировка каталога — `localizedStandardCompare`, чтобы совпадать с Finder.

## Тестирование

Ключевые части (event tap, Apple Events к Finder, оверлей поверх всех окон) требуют живого Finder и выданных разрешений — юнит-тестами не покрываются. Автотестами имеет смысл покрывать `ImageDirectory` (фильтрация, сортировка, навигация, границы) и `ImageCache` (окно предзагрузки). Остальное — ручная проверка; v0.1 по дорожной карте специально начинается с открытия файла из командной строки, чтобы оверлей можно было проверять без перехвата.
