## Что это

Ementium — agent-приложение для macOS (`LSUIElement`), подменяющее Quick Look для изображений: Пробел в Finder открывает выделенную картинку полноэкранным оверлеем, стрелки листают изображения каталога, Esc закрывает. Нет Dock-иконки, нет меню; единственный UI — окно настроек. Процесс работает постоянно: Esc закрывает только окно просмотра, выход — через настройки или menu bar. Настройки открываются по `⌘,` только в просмотре (обрабатывается самим окном просмотра) и при повторном запуске `.app` (`applicationShouldHandleReopen`).

## Сборка

Установлен Xcode 27 (`xcode-select -p` → `/Applications/Xcode.app/Contents/Developer`), `xcodebuild` доступен, Swift 6.4. Формат проекта выбран: обычный `Ementium.xcodeproj` (не SwiftPM и не XcodeGen). Минимальная версия — macOS 14 Sonoma.

Цель должна собираться как Universal binary (arm64 + x86_64), с выключенным App Sandbox и включённым Hardened Runtime + Apple Events.

## Архитектура: ключевые ограничения

Эти вещи определяют устройство кода и не выводятся из отдельных файлов.

**CGEventTap должен отвечать мгновенно.** Решение «поглотить Пробел или пропустить» принимается синхронно в callback. Любая блокирующая работа внутри — и система отключит tap с `kCGEventTapDisabledByTimeout`. Поэтому в callback **никаких межпроцессных вызовов**: ни Apple Events, ни Accessibility-запросов к Finder (даже «роль сфокусированного элемента» — это IPC, и при подвисшем Finder он может длиться сотни мс). Tap нужно уметь переподключать после отключения.

**Решение: кэш состояния Finder через `AXObserver`.** `FinderBridge` подписывается на уведомления Finder о смене фокуса и выделения, с задержкой ~50 мс обновляет кэш (фокус в текстовом поле? есть ли среди выделенных изображения?), а callback только читает кэш. Изображение — поглощаем; не-изображение, текстовое поле, неготовый или неактуальный кэш — пропускаем Пробел в Finder, и открывается родной Quick Look. Своя `QLPreviewPanel` и ресинтез Пробела отвергнуты. Неизвестно, отдаёт ли Finder выделение через AX во всех режимах (значки, список, колонки, галерея, рабочий стол) — это проверяет прототип v0.1; не считай это подтверждённым, пока прототипа нет.

**Выделение и сортировка.** Выделен один файл — листаем все изображения его каталога; несколько — только выделенные изображения. Сортировка всегда по имени; повторение сортировки окна Finder — в «Далее» дорожной карты.

**Никакого App Sandbox и никакого Mac App Store.** `CGEventTap` и управление Finder через Apple Events несовместимы с песочницей. Распространение только через Developer ID + нотаризацию (`notarytool`).

**Разрешения привязаны к подписи.** Нужны Accessibility (`AXIsProcessTrustedWithOptions`), возможно Input Monitoring (`CGPreflightListenEventAccess`), и Automation → Finder (`NSAppleEventsUsageDescription`). При разработке подпись меняется, и macOS «забывает» выданный доступ — приложение придётся удалять из списка в Системных настройках и выдавать доступ заново. Учитывай это при отладке: «не работает перехват» чаще означает слетевшее разрешение, а не баг в коде.

**Декодирование — через thumbnail, не через загрузку оригинала.** `CGImageSourceCreateThumbnailAtIndex` с ограничением по размеру экрана и `kCGImageSourceCreateThumbnailWithTransform` для EXIF-ориентации. Иначе RAW и большие фото съедят память. Кэш держит окно ±N вокруг текущего изображения.

**AppKit для оверлея, SwiftUI для настроек.** Окну просмотра нужен точный контроль уровня окна, фокуса и обработки клавиш — на SwiftUI это не делается. Настройки — `Settings` scene + `@AppStorage`.

**Тип файла — только через `UTType` (`conforms(to: .image)`)**, никогда по своему списку расширений. Если известно только имя файла (из AX-кэша), — `UTType(filenameExtension:)`. Сортировка каталога — `localizedStandardCompare`, чтобы совпадать с Finder.

## Тестирование

Ключевые части (event tap, Apple Events к Finder, оверлей поверх всех окон) требуют живого Finder и выданных разрешений — юнит-тестами не покрываются. Автотестами имеет смысл покрывать `ImageDirectory` (фильтрация, сортировка, навигация, границы, режим «только выделенные») и `ImageCache` (окно предзагрузки). Остальное — ручная проверка; v0.1 по дорожной карте специально начинается с открытия файла из командной строки, чтобы оверлей можно было проверять без перехвата.
