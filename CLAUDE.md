## Что это

Ementium — agent-приложение для macOS (`LSUIElement`), подменяющее Quick Look для изображений: Пробел в Finder открывает выделенную картинку полноэкранным оверлеем, стрелки листают изображения каталога, Esc закрывает. Нет Dock-иконки, нет меню; единственный UI — окно настроек. Процесс работает постоянно: Esc закрывает только окно просмотра, выход — через настройки или menu bar. Настройки открываются по `⌘,` только в просмотре (в режиме «следовать» — через `KeyInterceptor`, действие `.openSettings`), при повторном запуске `.app` (`applicationShouldHandleReopen`) и из меню иконки.

## Сборка

Xcode 27, Swift 6.4. Обычный `Ementium.xcodeproj` (формат Xcode 27) с синхронизируемыми папками: новый файл в `Ementium/`, `EmentiumTests/`, `EmentiumDecoder/` или `Shared/` попадает в target сам, `project.pbxproj` для этого не трогать. `Shared/` входит и в приложение, и в сервис. Минимальная версия — macOS 27, только Apple Silicon (macOS 27 на Intel не работает — Xcode собирает только arm64).

```bash
xcodebuild -project Ementium.xcodeproj -scheme Ementium build     # Debug
xcodebuild -project Ementium.xcodeproj -scheme Ementium test      # Swift Testing
xcodebuild -project Ementium.xcodeproj -scheme Ementium -configuration Release \
  -destination 'generic/platform=macOS' build                     # Release (arm64)
```

**Инкрементальная сборка может врать.** После добавления варианта в перечисление (`ViewerKeyAction.zoom`) тесты на инкрементальной сборке массово падали с бессмысленными значениями (`.step` вместо `.pass`), а на чистой — проходили. Странные падения после изменения типов — сначала прогнать на чистой папке (`-derivedDataPath` в новую). `install.sh` всегда собирает с нуля.

Проверка архитектуры: `lipo -archs …/Ementium.app/Contents/MacOS/Ementium` (ожидается `arm64`).

Песочница и hardened runtime — build settings (`ENABLE_APP_SANDBOX = NO`, `ENABLE_HARDENED_RUNTIME = YES`), файла `.entitlements` нет. `Info.plist` — частичный (только `CFBundleDocumentTypes`), остальное генерируется из `INFOPLIST_KEY_*`; в синхронизируемой папке он исключён из ресурсов через exception set.

Подпись — Apple Development, Personal Team `JW5WYVU2JQ` (бесплатный аккаунт); ею же подписан и релиз (в подписи видна почта Apple ID — так решено). Developer ID и нотаризации пока нет. **В Release `CODE_SIGN_INJECT_BASE_ENTITLEMENTS = NO`** у приложения и сервиса — иначе Xcode добавляет `get-task-allow` (отладчик может подключиться к процессу с разрешением Accessibility). Из-за этого песочница сервиса задана явно файлом `EmentiumDecoder/EmentiumDecoder.entitlements` (`ENABLE_APP_SANDBOX` работает через ту же подстановку). `scripts/release.sh` проверяет всё это и собирает DMG.

**Swift 6 и изоляция.** В app-target `SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor` и approachable concurrency: всё по умолчанию на главном акторе, а `nonisolated async` выполняется на акторе вызывающего. Чистая логика (`ImageDirectory`, `ViewerCommand`) помечена `nonisolated`, чтобы её можно было тестировать и звать откуда угодно. Фоновая работа — `@concurrent` (см. `ImageLoader.load`), иначе декодирование уйдёт на главный поток.

**Установка и запуск.** `scripts/install.sh` — единственный способ ставить приложение для проверки перехвата: собирает Release, кладёт одну копию в `/Applications` (прежнюю из `~/Applications`, если есть, убирает), снимает регистрацию промежуточных сборок в LaunchServices (иначе «Открыть в программе» ведёт в DerivedData) и запускает. `--no-open` — без запуска. `build/` помечен `.metadata_never_index`: Spotlight иначе заново регистрирует найденные там `.app`. Разрешение Accessibility привязано к подписи (Apple Development, стабильна) и переживает переустановку.

**Запуск для проверки оверлея без перехвата.** `open -a <путь к .app> файл`. Оверлей перекрывает **весь экран пользователя** поверх всех окон — предупреждай перед запуском и закрывай `pkill -x Ementium`. Наличие окна без скриншота: `CGWindowListCopyWindowInfo` по PID (bounds, layer, alpha). Логи — `/usr/bin/log show --predicate 'subsystem == "io.github.sdmn-code.Ementium"' --info`: в zsh голое `log` — встроенная команда оболочки. Сообщения `info` система держит только в памяти и через минуты стирает — смотреть сразу после проверки; что нужно найти и через час — `notice`.

## Архитектура: ключевые ограничения

**Три потока.** Главный: `AppDelegate`, просмотр, меню, разрешения. `FinderBridge` и `KeyInterceptor` — каждый на своём `RunLoopThread`, чтобы AX-запросы к занятому Finder (до сотен мс) не блокировали ни UI, ни event tap. Общаются только через `InterceptionState` (снимок под `OSAllocatedUnfairLock`). Решение о поглощении — чистая `InterceptionPolicy.decide`, покрыта тестами; при любом сомнении (снимок устарел, идёт дебаунс, фокус в тексте) — пропускать Пробел. Пока открыт просмотр, `isViewerVisible = true` и Пробел не перехватывается: Finder остаётся активным, а Пробел должен дойти до панели просмотра.

**Листание вслед за Finder (режим «следовать»).** Один файл, открытый Пробелом: панель просмотра не берёт клавиатуру (`ViewerPanel.acceptsKeyboard = false`), Finder остаётся активным, все нажатия разбирает `KeyInterceptor` через `InterceptionPolicy.followingAction` — только пока `isViewerVisible && isFollowingFinder && isFinderFrontmost`, иначе клавиатура в другом приложении была бы проглочена. Стрелки уходят в `FinderBridge.step` → заглядывание по элементам вида (`AXRows`; в значках/галерее порядок на всякий случай восстанавливается по координатам — экранный порядок в AX не гарантирован) → пачка стрелок `postToPid` до ближайшей картинки → новое выделение из AX → `onShow`. Рабочий стол (`AXGroup` прямо в `AXScrollArea` приложения, без окна) — исключение: стрелка Finder там идёт по пространству и на следующий ряд не переносится, поэтому шаг — сразу AX-выделение следующей картинки в порядке рядов (`DesktopOrder`, решение Саши), стрелок не шлём; шаг считается от текущего выделения Finder, без условия «автомат стоит на картинке». Порядок значков запоминается на время просмотра (`desktopOrder`: координаты — запрос на каждый значок) и перечитывается, если выделенного в нём нет. `⌘⌫` там не работает (не проверено прототипом). Автомат — чистый `FinderNavigation` (режимы idle/stepping/jumping/returning), покрыт тестами. Подводные камни, найденные прототипами и ревью: в «значках» → не переносится на новую строку (путь по сетке — `IconGridPath`), а слепая → из короткого последнего ряда уводит на значок выше — поэтому на краю ничего не слать; Finder создаёт элементы значков/галереи лениво; пока пачка в полёте, новое нажатие откладывать (`queuedStep`); таймаут края сначала перечитывает выделение. Системные сочетания — из `com.apple.symbolichotkeys` (`SystemShortcuts`), пользователь мог их переназначить. Несколько файлов и `open -a` — режим «свой список» (`ImageDirectory`, панель берёт клавиатуру).

Эти вещи определяют устройство кода и не выводятся из отдельных файлов.

**CGEventTap должен отвечать мгновенно.** Решение «поглотить Пробел или пропустить» принимается синхронно в callback. Любая блокирующая работа внутри — и система отключит tap с `kCGEventTapDisabledByTimeout`. Поэтому в callback **никаких межпроцессных вызовов**, в том числе Accessibility-запросов к Finder: прототип намерил до 290 мс на `AXFocusedUIElement`, когда Finder занят. Tap нужно уметь переподключать после отключения.

**Решение: кэш состояния Finder через `AXObserver`.** `FinderBridge` подписывается на уведомления Finder о смене фокуса и выделения, с задержкой ~50 мс обновляет кэш (фокус в текстовом поле? есть ли среди выделенных изображения?), а callback только читает кэш. Изображение — поглощаем; не-изображение, текстовое поле, неготовый или неактуальный кэш — пропускаем Пробел в Finder, и открывается родной Quick Look. Своя `QLPreviewPanel` и ресинтез Пробела отвергнуты.

Схема подтверждена прототипом `Prototypes/FinderAXProbe` (только на macOS 27; его README — источник фактов о структуре AX у Finder). Подписка — на элемент приложения Finder. Выделение: `AXFocusedUIElement` → `AXSelectedRows` (список, `AXOutline`) или `AXSelectedChildren` (значки, колонки, галерея, рабочий стол, результаты поиска) → `AXURL` у элемента или его потомка не глубже 2 уровней. **Apple Events не используются**, разрешения Automation нет: AX отдаёт полные пути, а Apple Events медленнее в 20–30 раз и местами врут. Известное ограничение: в колонках 100–250 мс после клика выделение пустое — Пробел уходит в Quick Look, это принято.

**Масштаб (v0.3).** Геометрия — `ZoomModel` (чистая, тесты). Жесты масштаба macOS отдаёт активному приложению (Finder), а не панели под курсором, поэтому сведение пальцев и двойное касание ловит `KeyInterceptor`: все жесты трекпада приходят в event tap **одним типом 29**, вид жеста (`.magnify`, `.smartMagnify`) — только через `NSEvent(cgEvent:)`; типы AppKit 30/32 на системном уровне не встречаются. Ловить при любом открытом просмотре (при двух выделенных картинках активен тоже Finder) и поглощать — иначе при активном Ementium жест придёт дважды. Прокрутка и клики приходят панели сами (`acceptsFirstMouse`). Курсор в режиме «следовать» сменить нельзя (фоновое приложение) — принято. Детали при увеличении: `loadDetailIfNeeded` декодирует оригинал до ~100 Мп. RAW: сначала встроенное превью (`ImageLoader.loadRawPreview`), потом подмена; без флага `FromImageAlways` ImageIO при отсутствии превью декодирует оригинал (проверено тестом).

**Смахивание (v1.1).** Прокрутка с фазами трекпада приходит панели в обоих режимах — перехват не нужен. Смахивание — только во «вписать» (увеличенную прокрутка двигает), автомат — чистый `SwipeTracker` (тесты). В режиме «следовать» смахивание не шлёт стрелки, а сразу выделяет показанный файл через AX (`FinderBridge.select(swipedTo:)`): стрелки при быстрых смахиваниях копились в очереди, и Finder секундами позже отыгрывал весь путь. Из запросов подряд выполняется последний (`swipeCount`), стрелка его отменяет. Просмотр показывает соседа сразу, ответы моста о прежних картинках пропускает (`swipeLead`); мост не подтвердил за 2 с — возврат к выделению Finder и его соседям. Соседи — по 3 с каждой стороны и так же далеко, как стрелки (до 1000 элементов: в «Недавних» между картинками десятки документов, с лимитом 50 смахивание упиралось в мнимый край). Места файлов в окне запоминаются на время просмотра (`itemURLs`), но выделяемый файл всегда сверяется с Finder заново; дальний поиск уступает любой команде (`commandCount`). Каждое смахивание — в логе, категория `swipe`.

**Сведения о снимке по `⌥`.** В режиме «следовать» модификаторы видит только перехват (маска tap включает `flagsChanged`). Событие изменения модификаторов **всегда пропускать** — проглоченное «залепит» модификатор у системы; просмотру — копия, и только при `isViewerVisible && isFollowingFinder && isFinderFrontmost`. `⌥` + стрелка — шаг (в Finder мост шлёт стрелку без модификаторов).

**Удаление в Корзину (`⌘⌫`) — самое опасное место кода.** `⌘⌫` удаляет то, что выделено в Finder, поэтому в `FinderBridge.performTrash` все проверки — прямо перед `postCommand`: стрелки долетели (`keysSettleTime`), Finder активен, фокус тот же (`CFEqual`), выделен ровно показанный файл; в просмотре — на экране именно он (`displayedFollowedImage`); автоповтор игнорируется (`InterceptionPolicy`). На выделение, которое ставит Finder после `⌘⌫`/`⌘Z`, **не полагаться** (прототип `FinderTrashProbe`): цель выбираем сами (`TrashTarget`) и выделяем через AX. `⌘Z` — только за своё (`trashed`) и только если файла нет на месте. Ослаблять эти проверки нельзя.

**Граница процессов: приложение не разбирает содержимое файлов.** Декодирование, кадры анимации и EXIF — только в XPC-сервисе `EmentiumDecoder` (песочница без файлов и сети, файл — дескриптором через `DecoderClient`). В коде `Ementium/` нельзя `CGImageSourceCreate…`, `CGAnimateImage…`, `CIRAWFilter`, `NSImage(contentsOf:/data:)`, `ImageLoader.load/decode`, `ImageMetadata.read` — это ловит `ProcessBoundaryTests`. `Shared/DecoderService.swift` собран и в приложении (для XPC-петли в тестах), но там не вызывается. Ответам сервиса не доверять (`DecodedImage.init?(coder:)` проверяет размеры и поверхность). Из данных ImageIO нужна подсказка типа (`ImageLoader.sourceOptions`) — без неё RAW читается как TIFF.

**Анимация** — свой проигрыватель (`ImageAnimator`): кадры у сервиса, всегда по кругу (число повторов из файла не учитывать: ImageIO сообщает `LoopCount = 1` и при его отсутствии). Тип — по `CGImageSourceGetType` (анимированный AVIF — `public.avis`; у него задержки в `{AVIS}` под общими именами ключей).

**Порядок листания** — всегда порядок окна Finder (следуем за его выделением). Не возвращайся к угадыванию сортировки или эвристикам по заголовку окна: это было опробовано и отвергнуто (сортировку по типу угадать не удалось; эксперимент удалён). Несколько выделенных файлов — только они, по имени.

**Никакого App Sandbox и никакого Mac App Store.** `CGEventTap` и чтение интерфейса Finder через Accessibility несовместимы с песочницей. Распространение только через Developer ID + нотаризацию (`notarytool`).

**Разрешения привязаны к подписи.** Нужны Accessibility (`AXIsProcessTrustedWithOptions`; в Системных настройках macOS 27 — «Управление устройством и доступ к данным», в текстах интерфейса название не пишем — кнопка ведёт прямо туда) и, возможно, Input Monitoring (`CGPreflightListenEventAccess`). При разработке подпись меняется, и macOS «забывает» выданный доступ — приложение придётся удалять из списка в Системных настройках и выдавать доступ заново. Учитывай это при отладке: «не работает перехват» чаще означает слетевшее разрешение, а не баг в коде.

**Декодирование — через thumbnail, не через загрузку оригинала.** `CGImageSourceCreateThumbnailAtIndex` с ограничением по размеру экрана и `kCGImageSourceCreateThumbnailWithTransform` для EXIF-ориентации. Иначе большие фото съедят память. Исключения: **RAW** — через `CIRAWFilter` со своим `CIContext` без кэша промежуточных результатов (через ImageIO тот же RAW раздувал память до 2,6 ГБ на время декодирования и оставлял ~400 МБ в системных кэшах; так — ~0,7–1,3 ГБ пик, ~40 МБ после и в 3–5 раз быстрее; встроенное превью — по-прежнему ImageIO); **SVG** — через `NSImage` (ImageIO его не рисует). Не возвращай RAW на ImageIO. `ImageCache` держит текущую и соседей (`PrefetchWindow`: 2 в сторону листания, 1 позади) и очищается при закрытии просмотра.

**Память.** Когда декодировали в процессе, после просмотра оставалось ~150–300 МБ — глобальный кэш CoreGraphics (выяснено `MallocStackLogging` + `malloc_history`/`leaks --trace`); после выноса в сервис приложение держит ~20–40 МБ, кэши уходят вместе с процессом сервиса. Замерять — `footprint <pid>`, а не «Мониторинг системы» сразу после закрытия.

**AppKit для оверлея, SwiftUI для настроек.** Окну просмотра нужен точный контроль уровня окна, фокуса и обработки клавиш — на SwiftUI это не делается. Настройки — четыре вкладки в панели инструментов (`NSTabViewController` .toolbar, `toolbarStyle = .preference`; «Основные», «Просмотр», «Управление», «О программе») с формами SwiftUI (`GeneralPane`, `ViewerPane`, `ControlsPane`, `AboutPane` в `SettingsView.swift`, `@AppStorage`) в панели `SettingsPanel` (`SettingsWindowController`), **не** сцена `Settings`: у агентского приложения открыть её из кода на macOS 14+ можно только недокументированным вызовом. Панель — неактивирующая (`.nonactivatingPanel`) и выводится `orderFrontRegardless`: из меню в строке меню macOS не даёт агентскому приложению активироваться, пока пользователь не щёлкнул по его окну (WindowServer: «activation count being 0»), и обычное окно открывалось без фокуса и под окнами активного приложения. Активацию просят `show()` и щелчок по панели (`SettingsPanel.sendEvent`; крестик — нет: активация пришла бы после закрытия, и Ementium остался бы впереди без окон). Активность — только `NSRunningApplication.current.isActive`: `NSApp.isActive` при ключевой неактивирующей панели `true`, хотя впереди другое приложение. При возврате на рабочий стол система агентское приложение не активирует, даже если оно было впереди (превращать панель в обычное окно не помогло), — окно поднимает `activeSpaceDidChange` (решение — чистый `SpaceReturnTracker`, тесты), а пока нас нет на его столе, оно плавает над обычными (`.floating`), иначе чужое окно на кадр мелькает поверх. Палитра цветов — свой `BackgroundColorWell` (создавать `init(frame:)`: `init(style:)` возвращает `NSColorWell`, а не подкласс). Не возвращай обычное `NSWindow`. Пустая сцена `Settings` в `EmentiumApp` осталась только потому, что `App` обязан объявить сцену; пункт `⌘,` подменён.

**Ключи настроек — только в `Preferences`** (ключи и значения по умолчанию); просмотр читает снимок `ViewerPreferences` при каждом открытии. Перехват и иконку `AppDelegate` применяет по `UserDefaults.didChangeNotification`.

**Уведомления `UserDefaults` приходят на чужом потоке.** Системный декодер RAW регистрирует свои defaults на фоновом потоке — `didChangeNotification` доставляется туда же, и `@objc`-обработчик на MainActor роняет приложение проверкой изоляции. Обработчик — `nonisolated`, с переходом на главный поток. То же правило для любых системных уведомлений через `NotificationCenter.default` с selector.

**Окно настроек не подгоняет размер под содержимое.** `sizingOptions = .preferredContentSize` + `.fixedSize` у прокручиваемой `Form` с переносом текста давали бесконечный цикл констрейнтов (полоса прокрутки → перенос → высота → …) и падение при запуске без разрешения. Размер задан явно, `sizingOptions = []`: высота каждой вкладки — константа по замеру скриншотов ru и en (`height(of:model:)`), у «Основных» она зависит от состояния (разрешение, «Готово», ожидание автозапуска). Меняешь содержимое вкладки — перемерь: заведомо большая высота, `screencapture -o -l <окно>`, низ содержимого по пикселям + 20 pt, больший из двух языков; смотри и сам скриншот — сноска у нижнего края легко ускользает от замера. Размер ведёт только `resizeToPane`: `preferredContentSize` у вкладок не задавать — `NSTabViewController` мгновенно подгоняет окно сам и дерётся с анимацией; анимацию — следующим проходом главного цикла (внутри смены вкладки AppKit обрывает её на первом кадре).

**Под тестами приложение-хозяин ничего не запускает** (`AppDelegate.isRunningTests` по `XCTestConfigurationFilePath`): иначе тесты включали бы перехват, автозапуск и открывали окна.

**Тип файла — только через `UTType` (`conforms(to: .image)`)**, никогда по своему списку расширений. AX-кэш даёт полный URL, тип берётся из `URLResourceValues.contentType`. Сортировка каталога — `localizedStandardCompare`, чтобы совпадать с Finder.

## Тестирование

Ключевые части (event tap, AXObserver на Finder, оверлей поверх всех окон) требуют живого Finder и выданных разрешений — юнит-тестами не покрываются. Автотестами (Swift Testing, `EmentiumTests/`) покрыты `ImageDirectory`, `ImageLoader` (на сгенерированных картинках, включая SVG), `ViewerCommand`, `ViewerView.fittedRect`, `InterceptionPolicy` (поглощение Пробела и разбор клавиш в режиме «следовать»), `SystemShortcuts` (на копии реальных настроек), `SwallowedKeys`, `FinderNavigation` (автомат листания на поддельном Finder), `IconGridPath`, `PrefetchWindow`, `ImageCache` (с подменным загрузчиком — `ImageCache.Loader`), `ZoomModel`/`ZoomMemory`, `InfoHoldTracker`, `ImageMetadata`, `SwipeTracker` и `SpaceReturnTracker`. Тестовые файлы — пустые, тип определяется по расширению. Внутри `#expect` нельзя вызывать `mutating`-методы — выноси результат в `let`. Остальное — ручная проверка; v0.1 по дорожной карте специально начинается с открытия файла из командной строки, чтобы оверлей можно было проверять без перехвата.
