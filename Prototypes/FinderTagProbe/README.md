# FinderTagProbe — цветные теги Finder из стороннего процесса

Исследовательский инструмент для v1.4 (метки клавишами 1–7): как ставить цветные теги на macOS 27, какие имена дают цвет и как Finder ведёт себя с выделением, когда метка меняется у выделенного файла.

## Запуск

```bash
cd ~/Documents/Obsidian/Claude/Ementium/Prototypes/FinderTagProbe
./run.sh auto                    # запись и чтение, имена, ошибки, дата изменения (testdata/auto)
./run.sh labels                  # NSWorkspace.fileLabels: имена, номера, цвета
./run.sh resolve                 # имена цветных тегов на языке системы — способ, рекомендованный для приложения
./run.sh color Имя…              # какой цвет система даёт имени
./run.sh labelnumber             # старый ярлык по номеру цвета (labelNumberKey)
./run.sh setup                   # папка testdata/finder: 12 картинок и документ, открывается в Finder
./run.sh toggle <файл> <1…7>     # переключить метку (порядок меню Finder)
./run.sh show <файл>             # теги файла: API, сырой атрибут, ярлык, даты
```

Логи — в `logs/`, тестовые файлы — в `testdata/` (в git не попадают). Для проверок в Finder: `sleep 3 && ./run.sh toggle …` — успеть переключиться в Finder.

## Результаты (18.10.2026, macOS 27, система на русском)

| Вопрос | Ответ |
|---|---|
| 1. Запись | `(url as NSURL).setResourceValue(names, forKey: .tagNamesKey)` работает. Пишется весь список, поэтому чужие теги сохраняются, если прочитать список, изменить и записать. Свой тег («Работа») и его порядок не теряются. Система хранит список в атрибуте `com.apple.metadata:_kMDItemUserTags` как «имя\nномер цвета» |
| 2. Имена цветов | Цвет даёт только имя цветного тега **на языке системы**: «Красный» → цвет 6. Регистр и «ё» не важны: «красный», «Желтый» и «Жёлтый» — цветные. «Red» на русской системе, «Фиолетовый», «Rot», «Красный » с пробелом дают **бесцветный** тег (цвет 0). `NSWorkspace.fileLabels` отдаёт имена на языке **программы** (у утилиты без локализации — английские, даже с `-AppleLanguages ru`), поэтому сам по себе ненадёжен. Порядок `fileLabels` — по номеру ярлыка: 0 None, 1 серый, 2 зелёный, 3 лиловый, 4 синий, 5 жёлтый, 6 красный, 7 оранжевый; меню Finder — номера 6, 7, 5, 2, 4, 3, 1 |
| 2. Рекомендованный способ | `resolve`: кандидаты — избранные теги Finder (`UserDefaults(suiteName: "com.apple.finder")`, ключ `FavoriteTagNames` — язык системы, в нём «Желтый» и «Зеленый» без «ё») и `fileLabels`. Каждый кандидат записывается во временный файл, номер цвета читается из атрибута — цвет определяет сама система. ~0,1 с на всё. Переименованный в настройках Finder тег («Красный» → «Тест») находится под новым именем |
| 2. Старый ярлык | `labelNumberKey` пишет только старый ярлык в `com.apple.FinderInfo`; имя тега API достраивает на языке программы («Red»), а при любом другом теге файла ярлык в списке не виден. Ярлык у файла один — для складывающихся меток не годится |
| 3. Скорость | Метка появляется в окне Finder сразу во всех видах: список, значки, колонки, галерея, поиск |
| 4. Выделение | Остаётся на файле, вид не перестраивается (без группировки и сортировки по тегам) |
| 5. Ошибки | Нет прав на запись (0444) и защищённый файл (`uchg`) — `NSOSStatusErrorDomain -5000`. Том только для чтения — `-61`, теги на нём читаются. Файла нет — `-43`. SMB и незагруженный файл iCloud не проверены — не было под рукой |
| 6. Группировка по тегам | Файл переезжает в другую группу, **выделение снимается**. Стрелка вниз после этого выделяет первый файл списка |
| 6. Сортировка по тегам | Файл переезжает в списке, **выделение едет вместе с ним** |
| 6. Смарт-список тега | После снятия метки файл исчезает из списка **вместе с выделением**, другой файл выделения не получает. В приложении (журнал): Finder сначала снимает выделение, а файл убирает через **1,6–2,1 с**. Выделить файл снова в этот промежуток нельзя — выделенный файл Finder из результатов не убирает, и он остаётся в списке |
| 7. Дата изменения | **Не меняется** (`st_mtime` тот же), меняется только время изменения атрибутов (`st_ctime`). Дата создания не меняется. Сортировка по дате изменения не поедет |
| 8. Отмена в Finder | Запись через `tagNamesKey` в историю отмены Finder **не попадает**: «Правка → Отменить» остаётся серым. Метка, поставленная в самом Finder, туда попадает («Отменить добавление тега Красный») |

## Выводы для приложения

- Писать список целиком: прочитать теги, переключить один, записать (`TagToggle`).
- Имена цветов определять `resolve`-способом, а не `fileLabels` и не по своему словарю.
- Режим «следовать», группировка по тегам: после записи вернуть выделение на показанный файл через AX. Смарт-список тега: файл уходит из окна — выбирать цель заранее, как `TrashTarget`.
- `⌘Z` по меткам Ementium выполняет сам, история Finder не затрагивается.
- Ошибки `-5000`, `-61`, `-43` → понятное сообщение.
