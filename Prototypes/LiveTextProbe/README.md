# LiveTextProbe — VisionKit и «Поделиться» в панели просмотра

Исследовательский инструмент для v1.3 (Live Text, «Поиск по изображению», «Поделиться» по удержанию `⌘`).
Окно устроено как просмотр Ementium: неактивирующая панель уровня `.screenSaver`, картинка — `CALayer`
с `IOSurface` в формате сервиса декодирования (BGRA), распознавание — `ImageAnalyzer` по `CVPixelBuffer`
из этой поверхности. Без файла — сгенерированная картинка с русским и английским текстом, телефоном, ссылкой, датой.

## Запуск

```bash
cd ~/Documents/Obsidian/Claude/Ementium/Prototypes/LiveTextProbe
./run.sh measure [файлы…]          # время распознавания: экранная версия и полное разрешение
./run.sh align [файл]              # окно 1200×800 на ~8 с: выделение при масштабе и повороте, снимки в logs/
./run.sh sharetest                 # меню «Поделиться» при панели .screenSaver и .statusBar: окна и уровни
./run.sh clicktest                 # мышь сквозь оверлей вне режима ⌘ и выделение в режиме
./run.sh pilltest                  # «пилюли»: карточка телефона и просмотр ссылки — открытие и закрытие
./run.sh classdump Класс…          # методы и переменные частных классов VisionKit и DataDetectors
./run.sh ddcheck                   # сигнатура requestBubbleClosureUnanchorOnFailure: (как проверяет Ementium)
./run.sh overlay [файл] [--follow] # интерактивно, на весь экран
```

`overlay`: удержание `⌘` ~0,3 с — режим (кнопки, выделение); `Z` — масштаб, `R` — поворот, `H` — подсветка,
`⌘C` — текст, `⌘L` — поиск по изображению, `⌘S` — поделиться, `D` — дерево оверлея, `Esc` — выход.
`--follow` — клавиатура у другого приложения (как режим «следовать»): клавиш нет, `⌘` опрашивается,
выход — кнопка «✕ Выход» или `Esc` (глобальный монитор, если у Терминала есть доступ).

`pilltest` (окно 1200×800 на ~10–30 с) управляется переменными окружения: `EVENTS=1` — щелчок событиями мыши
через очередь приложения (как настоящий), иначе `performClick`; `MONITOR=1` — монитор щелчков как в Ementium,
`MODE=swallow|swallowpair|passthrough` — что он делает со щелчком при открытой карточке; `TRACE=1` — вызовы
DataDetectors и VisionKit в лог; `LINK=1` — просмотр ссылки и способы его закрыть (`STEP=` — один способ);
`NOKEY=1` — панель не ключевая, как в режиме «следовать»; `KEYTRICK=makekey|makekey-quick|monitor|pretend` — как
панели стать ключевой на время щелчка по ссылке; `PILL=phone` — то же с «пилюлей» телефона; `LINKTOGGLE=1` — «пилюля» ссылки как переключатель (`NOSWALLOW=1` —
щелчок не поглощать); `FULL=1` — панель на
весь экран; `QUIET=1` — без дерева видов.

Логи и снимки — в `logs/` (в git не попадает).

## Результаты (16.10.2026, macOS 27)

| Вопрос | Ответ |
|---|---|
| Языки | `ru-RU`, `uk-UA` и ещё 30; русский текст, телефон, ссылка, дата находятся, мелкий текст (30 px на 3000) — тоже |
| Время анализа | первый вызов ~300–400 мс (прогрев), дальше ~100 мс на экранную версию 2560; 36 Мп без текста — 55–65 мс |
| Граница процессов | `analyze(CVPixelBuffer)` из `IOSurface` (`CVPixelBufferCreateWithIOSurface`) — файл приложению не нужен |
| `contentsRect` | единичные координаты, ось Y — **сверху вниз** (в пунктах вида — выделение не рисуется) |
| Масштаб и поворот | оверлей **ровно на картинке** (`frame` = показанный прямоугольник, масштабируется с ней), `contentsRect` = (0, 0, 1, 1), анализ с `orientation` поворота показа — выделение совпадает при масштабе, 90°/180° и их сочетании. Оверлей на весь вид при `contentsRect` за пределами (0…1) — съезжает |
| Кнопки VisionKit | Live Text и быстрые действия («Translate», ссылка, телефон, дата) — у нижнего края **видимой части картинки**, при увеличении не уходят за экран. Свою кнопку ставить по фактическому положению `VKImageAnalysisButton` (`supplementaryInterfaceContentInsets` резервирует место), иначе наезжает |
| `hasText(at:)` | для проверки совпадения не годится: при увеличении «да» везде, при вписанной картинке «нет» везде |
| Режим `⌘` | взаимодействия не выключать (`preferredInteractionTypes = []` сбрасывает выделение) — запрещать начало новых в `shouldBeginAt`. Вне режима мышь проходит сквозь оверлей к картинке (сдвиг работает), в режиме протяжка выделяет текст и не двигает; выделение переживает отпускание `⌘` |
| Ссылка, телефон, дата | щелчок открывает карточку номера (дочернее окно панели — поверх неё) / просмотр страницы (окно другого процесса — см. «Просмотр ссылки» ниже) |
| «Поиск по изображению» | программно не открыть; кнопка — `VKCVisualSearchCornerView` («Visual Look Up»), видна, только если есть что искать. На проверочном Mac недоступен и в стандартном Quick Look (фото кошки) — вероятно, регион/язык; `hasResults(.visualLookUp)` = false |
| «Поделиться» | меню — окно уровня 101 (`.popUpMenu`): под панелью `.screenSaver` (1000) его не видно, а невидимое меню забирает события (после `⌘S` залипал режим). При панели `.statusBar` (25 — выше строки меню и Dock) меню над ней |
| Кнопка «Поделиться» | ставить справа от `VKImageAnalysisButton` **после** анимации появления кнопок VisionKit (посреди неё — не на той высоте); `supplementaryInterfaceContentInsets` снизу 8, справа 8 + 26 + 8 — обе кнопки с отступом 8 pt от краёв |
| Кнопка Live Text | подсвечивает весь текст и быстрые действия; `highlightSelectedItemsDidChange` → **режим фиксируется**: `⌘` можно отпустить, выделение и «пилюли» работают; повторное нажатие снимает. Так ждёт пользователь (как в Quick Look) |
| Быстрые действия | телефон — карточка контакта, ссылка — предварительный просмотр, почта — почтовое приложение (в фоне). В `--follow` всё так же, **кроме просмотра ссылки** — он не открывается (нужна активация приложения, а в режиме «следовать» Finder должен оставаться впереди) |
| Сервисы «Поделиться» | AirDrop — окна **нашего** процесса уровня 3 (во весь экран): на время сервиса панель — обычного уровня, по `sharingService(_:didShareItems:)` / `didFailToShareItems` — обратно `.screenSaver`, иначе видны строка меню и Dock. «Добавить в Фото» — без интерфейса, `didShare` через ~0,25 с; нужна подсказка на экране. «Сообщения» — `didShare` уже через ~0,15 с, дальше — окно приложения «Сообщения» (другой процесс, уровень 0): вернуть панель наверх — закрыть его; вложение доходит (проверено в приложении: просмотр закрывается, процесс Ementium жив) |
| Сервис в другом приложении | если после выбора сервиса активируется другое приложение — просмотру уйти с дороги (в приложении — закрыться; процесс Ementium продолжает жить) |
| «Пилюли» | `VKCActionInfoButton` (`NSButton`), текст данных — в `title`; их действие — пункт меню DataDetectors (`runActionForDictionary:`). Карточка телефона — `DDPopover` (`NSPopover`, transient, делегат — он сам) с `DDActionViewController`, содержимое — `NSRemoteView` (другой процесс): кнопки «Отменить» в своём процессе нет. `performClose` и `-[DDActionsManager requestBubbleClosureUnanchorOnFailure:]` карточку не закрывают, `close()` — закрывает, учёт DataDetectors после него чистый |
| Повторный щелчок по «пилюле» | пока карточка открыта, на рамке окна висит её распознаватель (`NSPressGestureRecognizer`), щелчок мимо достаётся ему. Если монитор щелчок **поглощает** (и закрывает карточку), следующий щелчок до «пилюли» не доходит — открывает только четвёртый (так было в приложении). Если **пропускает** и закрывает карточку следующим проходом — открыть/закрыть чередуются ровно (`MODE=passthrough`) |
| `performClick` по «пилюле» после закрытия | DataDetectors проверяет `+hitWindowIsPopover` по `NSApp.currentEvent.window`: без настоящего события там остаётся окно закрытой карточки (~6 с), и «пилюля» молчит. Настоящих щелчков это не касается |
| Просмотр ссылки | окно `com.apple.quicklook.ui.helper` («Вспомогательное…»), 1060×475. Панель ключевая — уровень на 1 выше панели (1001) и место у окна; не ключевая (режим «следовать») — уровень 101, под панелью, и левый нижний угол экрана. Размер и место выбирает он сам (VisionKit передаёт ему негодную рамку «пилюли» — в системном журнале «Bogus highlightFrame») |
| Просмотр ссылки в режиме «следовать» | панель на время щелчка — ключевая (`makeKey` в мониторе щелчков, если щёлкнули по `VKCActionInfoButton` / `VKCDataDetectorElementView`): окно — как в своём списке (1001, у окна). Подмена `isKeyWindow` не помогает — важна настоящая ключевая. Клавиатуру можно вернуть (`NSApp.deactivate()`) сразу после щелчка: окно ссылки и карточка контакта остаются открытыми |
| Повторный щелчок по «пилюле» ссылки | VisionKit на каждый щелчок сначала просит DataDetectors закрыть «пузыри», потом открывает просмотр снова — окно переоткрывается. Переключатель: пока окно открыто, щелчок по панели закрывает его (`requestBubbleClosureUnanchorOnFailure:`) и поглощается целиком — нажатие и отпускание. Открыть/закрыть чередуются ровно и с ключевой панелью, и в режиме «следовать»; своего распознавателя в нашем окне у просмотра ссылки нет, поглощение ничего не сбивает (в отличие от карточки) |
| Закрыть просмотр ссылки | не закрывают: `analysis = nil`, тот же анализ ещё раз, `resetSelection`, скрытие кнопок, `orderOut` панели, синтетическое нажатие `⌘`. Закрывает `-[DDActionsManager requestBubbleClosureUnanchorOnFailure:NO]` (~0,3 с) — так же VisionKit закрывает его, когда перестраивает «пилюли» после нового анализа; `nil`, затем прежний анализ — тоже, но асинхронно, и только если анализ остался |
| Строка меню и Dock | панель уровня 25 закрывает их полностью при любых настройках окна просмотра (прозрачность, `collectionBehavior`) и при открытом просмотре ссылки. Сквозь полупрозрачный фон просмотра они видны — это не «поверх» |
