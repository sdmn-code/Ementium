# FinderFollowProbe — прототип «следовать за Finder»

Одноразовый исследовательский инструмент. Проверяет подход, при котором Ementium не строит свой список
для листания, а отправляет стрелки в Finder и показывает то, что Finder выделил. Так порядок листания
всегда совпадает с окном Finder: любая сортировка, группы, «Недавние», поиск.

## Что проверяется

- Доходят ли синтетические стрелки до Finder, пока поверх экрана висит оверлей, не забирающий клавиатуру
  (как будет у Ementium), — в видах «список», «колонки», «значки», «галерея».
- Каким способом отправки: как с клавиатуры (HID), в поток событий сессии или напрямую процессу Finder.
- Сколько миллисекунд проходит до смены выделения.
- Что на краю списка; переходит ли → в «значках» на следующую строку; что делает ↓ в «галерее».
- Не уходит ли фокус от Finder.

## Запуск

Из Terminal.app (ему нужен «Универсальный доступ», как для FinderAXProbe):

```bash
cd ~/Documents/Obsidian/Claude/Ementium/Prototypes/FinderFollowProbe
./run.sh auto     # ~1,5 минуты на папке FinderAXProbe/testdata/many, мышь и клавиатуру не трогать
./run.sh manual   # в Finder: кликнуть файл, нажать ⌃⌥Пробел — прогон на этом окне; Ctrl+C — итог
```

Логи — в `logs/` (в git не попадают).

## Режимы

- `auto` — доставка стрелок во всех видах тремя способами, край, перенос → в значках, ↓ в галерее.
- `manual` — прогон на текущем окне по ⌃⌥Пробел. **Не работает**: ⌃⌥Пробел — системное «следующий источник ввода», система забирает его раньше перехвата.
- `burst` — прыжок пачкой стрелок через документы до картинки (папка `mixed`: картинка, 40 документов, картинка, 5, картинка).
- `icons` — последовательное листание в «значках»: путь по сетке против установки выделения через AX.

## Результаты (11.10.2026, macOS 27)

**Доставка стрелок (`auto`).** Все три способа (HID, session, напрямую процессу) доходят во всех видах; оверлей с `canBecomeKey = false` фокус у Finder не забирает. Задержка до смены выделения: значки ~20 мс, галерея ~25, список 20–40, колонки 60–70 (до 180 мс, пока строится колонка предпросмотра). «Список не реагирует на ↓» — выделение стояло на последней строке (сортировка по убыванию), а не сбой. Край: Finder просто не двигается. В значках → **не переносится** на следующую строку; в галерее ↓ ничего не делает.

**Пачка (`burst`).** 41 стрелка подряд — Finder дошёл точно до цели за 0,83 с в «колонках» (~20 мс на шаг), 6 стрелок — 0,14 с; ни одна стрелка не потерялась и не склеилась. Заглядывание вперёд по AX — ~2 мс на элемент. В «галерее» элементы создаются только рядом с выделенным — картинка в 41 элементе впереди не видна.

**Значки (`icons`).** Порядок элементов в AX не обязательно совпадает с экранным (в прогоне первый на экране значок оказался в AX вторым; подтвердить не удалось) — в приложении порядок на всякий случай восстанавливается по координатам. Путь по сетке («по ряду, потом вниз»): 3 из 4 точно, 230–280 мс; промах — из короткого последнего ряда → уходит в пустоту, поэтому вверх нужно сначала вверх. Установка `AXSelectedChildren` у коллекции работает (7–12 мс), но прокрутку окна к цели не проверяли — выбран путь по сетке. Позже в приложении выяснилось: слепая → из короткого последнего ряда уводит на ближайший значок справа в ряду выше — на краю ничего не слать.

Выводы вошли в v0.2.2: листание вслед за выделением Finder, прыжок пачкой, последовательные «значки».
