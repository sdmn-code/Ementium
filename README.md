# Ementium

**Ementium** — минималистичный просмотрщик изображений для macOS, который заменяет стандартный Quick Look для картинок. Выделите изображение в Finder, нажмите **Пробел**, и оно откроется на весь экран поверх затемнённого фона. Стрелками листаются остальные изображения в той же папке, **Esc** закрывает просмотр.

Интерфейса почти нет: нет панелей, кнопок и Dock-иконки. Есть только окно настроек.

## Идея

Встроенный Quick Look удобен, но для просмотра фотографий у него есть недостатки: окно не занимает весь экран, вокруг остаются элементы интерфейса, а листать папку можно только при выделении нескольких файлов. Ementium сохраняет привычный жест (Пробел в Finder) и делает следующее:

- открывает изображение сразу на весь экран;
- затемняет всё вокруг, чтобы ничего не отвлекало;
- позволяет листать все изображения каталога, а не только выделенные;
- закрывается одной клавишей.

## Возможности

- Перехват клавиши **Пробел** в Finder, когда выделено изображение.
- Файлы, которые не являются изображениями (PDF, видео, документы и др.), Ementium не трогает: Пробел уходит в Finder, и открывается стандартный Quick Look.
- Полноэкранный показ поверх всех окон с регулируемым уровнем затемнения фона.
- Навигация стрелками по изображениям текущего каталога. Остальные файлы приложение «не видит». Если в Finder выделено несколько файлов, листаются только выделенные изображения, как в Quick Look.
- Предзагрузка соседних изображений, чтобы листание было мгновенным.
- Показ на том мониторе, где находится активное окно Finder.
- Работа в фоне без иконки в Dock (агентское приложение).
- Автозапуск при входе в систему.
- Окно настроек — единственный элемент интерфейса.

## Управление

| Клавиша                | Действие                                                      |
| ---------------------- | ------------------------------------------------------------- |
| `Пробел` (в Finder)    | Открыть выделенное изображение                                |
| `→` / `↓`              | Следующее изображение в каталоге                              |
| `←` / `↑`              | Предыдущее изображение в каталоге                             |
| `Esc`                  | Закрыть просмотр                                              |
| `Пробел` (в просмотре) | Закрыть просмотр (как в Quick Look, отключается в настройках) |
| `Home` / `End`         | Первое / последнее изображение (план)                         |
| `⌘,` (в просмотре)     | Открыть настройки                                             |
| `⌘Q` (в просмотре)     | Завершить Ementium                                            |
| `+`                    | Увеличить масштаб (v0.3)                                      |
| `-`                    | Уменьшить масштаб (v0.3)                                      |

> **Примечание.** `Esc` закрывает окно просмотра, но не завершает само приложение: процесс Ementium должен работать постоянно, иначе перехват Пробела в Finder перестанет работать. Полностью выйти можно через `⌘Q` в просмотре, окно настроек или пункт в строке меню (если он включён).

> **Как открыть настройки.** Клавиши получает только активное приложение, а Ementium активен лишь пока открыт просмотр. Поэтому `⌘,` работает только в просмотре: в Finder это сочетание открывает настройки самого Finder. Без открытого просмотра настройки открываются повторным запуском Ementium (из «Программ», Spotlight или Launchpad) или через иконку в строке меню, если она включена.

## Поддерживаемые форматы

Декодирование выполняет системный фреймворк **ImageIO**, поэтому набор форматов зависит от версии macOS.

| Формат | Расширения | Примечание |
|---|---|---|
| JPEG | `.jpg`, `.jpeg` | |
| PNG | `.png` | |
| HEIF / HEIC | `.heic`, `.heif` | |
| TIFF | `.tif`, `.tiff` | |
| GIF | `.gif` | Анимация — в плане |
| BMP | `.bmp` | |
| WebP | `.webp` | Только чтение |
| AVIF | `.avif` | |
| JPEG XL | `.jxl` | |
| PSD | `.psd` | Отображается сведённое изображение |

Перед выпуском список нужно проверить на минимальной поддерживаемой версии (macOS 14), особенно AVIF и JPEG XL. Определять тип файла следует через `UTType` (соответствие `public.image`), а не по расширению.

## Как это работает

Приложение состоит из нескольких независимых компонентов.

```
┌──────────┐  уведомления AX  ┌──────────────────────────┐
│  Finder  │─────────────────▶│ FinderBridge             │
└────┬─────┘                  │ кэш: фокус, выделение,   │
     │                        │ «это изображение?»       │
     │                        └────────────┬─────────────┘
     │ Пробел                              │ чтение кэша
     ▼                                     ▼
┌────────────────────────────────────────────────────────┐
│ KeyInterceptor                                         │
│ изображение → поглотить, иначе → пропустить в Finder   │
└───────────────────────────┬────────────────────────────┘
                            │ URL выделенных файлов
                            ▼
┌───────────────┐   список   ┌────────────────────────────┐
│ ViewerWindow  │◀───────────│ ImageDirectory             │
│ (оверлей)     │            │ + ImageCache               │
└───────────────┘            └────────────────────────────┘
```

Главный принцип: callback перехвата не обращается к другим процессам. Всё, что нужно знать о Finder для решения «поглотить или пропустить», `FinderBridge` вычисляет заранее и держит в кэше.

### 1. `KeyInterceptor` — перехват клавиатуры

- Использует **`CGEventTap`** на уровне сессии и слушает события `keyDown`.
- Поглощает Пробел, только если выполнены все условия:
  - активное приложение — Finder (`com.apple.finder`);
  - нажат Пробел без модификаторов;
  - по кэшу `FinderBridge` фокус не в текстовом поле (переименование файла, поиск, адресная строка);
  - по кэшу `FinderBridge` среди выделенных файлов есть изображение.
- Если условия выполнены, событие поглощается (callback возвращает `nil`), и Quick Look не открывается. Иначе событие пропускается в Finder без изменений, и для PDF, видео и прочих файлов открывается стандартный Quick Look.
- Если кэш не готов или не актуален (Finder только что запущен, режим отображения не поддерживается), Пробел тоже пропускается. Хуже, чем без Ementium, в этом случае не будет.
- Callback должен работать очень быстро: если он задерживается, система отключает tap (`kCGEventTapDisabledByTimeout`). Поэтому внутри callback нет Accessibility-запросов к Finder, только чтение кэша. Tap после отключения повторно включается.

### 2. `FinderBridge` — состояние Finder

- Подписывается через **`AXObserver`** на элемент приложения Finder: уведомления `AXFocusedUIElementChanged`, `AXSelectedRowsChanged`, `AXSelectedChildrenChanged`. Опроса нет: код выполняется только при событиях в Finder.
- По уведомлению обновляет кэш: в текстовом ли поле фокус (роль `AXTextField` / `AXTextArea` и изменяемое `AXValue`), какие файлы выделены и есть ли среди них изображения.
- Выделение читается так: `AXFocusedUIElement` приложения → `AXSelectedRows` (список) или `AXSelectedChildren` (значки, колонки, галерея, рабочий стол) → полный путь из `AXURL` у элемента выделения или его потомка.
- Обновление выполняется с небольшой задержкой (~50 мс) после того, как выделение перестало меняться. Так при быстром пролистывании списка стрелкой Finder не засыпается запросами.
- Тип файла определяется через `UTType` по URL (`contentTypeKey`), а не по собственному списку расширений.
- Apple Events не используются: Accessibility отдаёт полные пути быстрее и надёжнее.
- Работоспособность подтверждена прототипом [FinderAXProbe](Prototypes/FinderAXProbe/README.md) на macOS 27: все режимы отображения, рабочий стол, результаты поиска, iCloud Drive, сетевой диск. Обновление кэша занимает около 2 мс, но при занятом Finder доходит до 300 мс.

### 3. `ImageDirectory` — список изображений каталога

- Если выделен один файл, перечисляет файлы его каталога и оставляет только изображения (`UTType.conforms(to: .image)`).
- Если выделено несколько файлов, список состоит только из выделенных изображений, как в Quick Look.
- Всегда сортирует по имени: `localizedStandardCompare` (естественная сортировка, как в Finder: «file2» перед «file10»). Текущая сортировка окна Finder (по дате, размеру и т. д.) не учитывается, это в планах (см. [Дорожную карту](#дорожная-карта)).
- Определяет индекс текущего файла и обрабатывает переходы к соседним.

### 4. `ImageCache` — загрузка и предзагрузка

- Декодирует изображения через `CGImageSourceCreateThumbnailAtIndex` с ограничением по размеру экрана, а не загружает оригинал целиком. Это важно для больших фото и RAW.
- Учитывает EXIF-ориентацию (`kCGImageSourceCreateThumbnailWithTransform`).
- Держит в памяти текущее изображение и несколько соседних (окно ±N), остальные выгружает.
- Загрузка выполняется в фоне, интерфейс не блокируется.

### 5. `ViewerWindow` — окно просмотра

- Безрамочное `NSPanel` / `NSWindow` на весь экран (`styleMask: .borderless`), уровень выше обычных окон.
- Фон — чёрный с настраиваемой прозрачностью, изображение по центру: большие вписываются в экран, маленькие показываются в естественном размере и не растягиваются.
- Естественный размер: 1 пиксель = 1 пункт экрана. Исключение — Retina-снимки с 144 и 216 dpi (скриншоты): у них 2 и 3 пикселя на пункт, чтобы скриншот окна был размером с само окно. Остальной DPI (240, 300 у экспорта и сканов) игнорируется.
- Плавное появление и исчезновение (fade).
- Окно — панель, которая получает клавиатуру, не активируя приложение (как Spotlight). При закрытии фокус возвращается приложению, из которого открыли просмотр.
- Если фокус ушёл в другое приложение (⌘Tab, Spotlight, уведомление), просмотр закрывается сам — иначе оверлей висел бы поверх всего без возможности закрыть его клавишей. Клик по фону просмотр не закрывает.
- Пока открыт просмотр, все ⌘-сочетания, кроме описанных в «Управлении», поглощаются.
- Все клавиши, включая `⌘,`, обрабатываются самим окном просмотра: строки меню у агентского приложения нет.
- Реализация на **AppKit**, так как нужен точный контроль над уровнем окна, фокусом и обработкой клавиш.

### 6. `Settings` — окно настроек

- Реализация на **SwiftUI** (`Settings` scene).
- Хранение настроек в `UserDefaults` / `@AppStorage`.

### Жизненный цикл приложения

- `LSUIElement = YES` в `Info.plist`: нет иконки в Dock и главного меню.
- Автозапуск через `SMAppService.mainApp` (ServiceManagement).
- При первом запуске открывается окно настроек с инструкцией по выдаче разрешений.
- Повторный запуск уже работающего Ementium открывает окно настроек (`applicationShouldHandleReopen`).

## Системные разрешения

Без этих разрешений перехват работать не будет. Приложение должно проверять их при запуске и показывать понятную инструкцию.

| Разрешение | Зачем | Как проверить |
|---|---|---|
| **Универсальный доступ** (Accessibility) | Создание `CGEventTap`, поглощение событий, `AXObserver` для отслеживания фокуса и выделения в Finder | `AXIsProcessTrustedWithOptions` |
| **Мониторинг ввода** (Input Monitoring) | На macOS 27 для перехвата не понадобился. Запрашивается, только если event tap не создаётся при выданном «Универсальном доступе» | `CGPreflightListenEventAccess` / `CGRequestListenEventAccess` |

Разрешения привязаны к подписи приложения. При разработке с меняющейся подписью macOS может «забыть» выданный доступ, тогда его нужно удалить и выдать заново в **Системные настройки → Конфиденциальность и безопасность**.

## Требования

- macOS 14 Sonoma или новее.
- Xcode 27 или новее: проект сохранён в формате Xcode 27, более старые версии могут его не открыть.
- Swift 6 (строгая проверка конкурентности).
- Apple Silicon и Intel (Universal binary).

## Сборка и запуск

```bash
git clone <url-репозитория>
cd Ementium
open Ementium.xcodeproj
```

1. В Xcode выберите свою команду разработчика: **Signing & Capabilities → Team**. App Sandbox в проекте уже выключен, Hardened Runtime включён.
2. Соберите и запустите схему `Ementium` (`⌘R`). Окон при запуске нет: это агентское приложение без иконки в Dock.
3. Откройте изображение:
   ```bash
   open -a Ementium путь/к/картинке.jpg          # весь каталог
   open -a Ementium a.jpg b.png                  # только эти файлы
   ```
   Того же можно добиться через **Открыть в программе → Ementium** в контекстном меню Finder.
4. Для перехвата Пробела установите приложение скриптом — он собирает Release, кладёт единственную копию в `~/Applications` и запускает её:
   ```bash
   scripts/install.sh            # собрать, установить, запустить
   scripts/install.sh --no-open  # без запуска
   ```
   При первом запуске macOS покажет диалог «Универсального доступа»: включите Ementium в Системных настройках, перехват заработает сам, без перезапуска. Статус — в меню иконки в строке меню.

Из терминала:

```bash
xcodebuild -project Ementium.xcodeproj -scheme Ementium build    # Debug, только текущая архитектура
xcodebuild -project Ementium.xcodeproj -scheme Ementium test     # тесты
xcodebuild -project Ementium.xcodeproj -scheme Ementium -configuration Release \
  -destination 'generic/platform=macOS' build                    # Universal: arm64 + x86_64
```

Для распространения вне Mac App Store приложение нужно подписать сертификатом **Developer ID** и пройти **нотаризацию** (`notarytool`).

## Ограничения

- **Нет App Sandbox, нет Mac App Store.** Глобальный перехват клавиатуры через `CGEventTap` и чтение интерфейса Finder через Accessibility несовместимы с песочницей, а приложения без песочницы нельзя публиковать в Mac App Store. Распространение — через Developer ID и нотаризацию.
- Работа зависит от поведения Finder. Обновления macOS могут изменить структуру Accessibility-элементов Finder. Прототип проверен только на macOS 27, на минимальной версии (macOS 14) её нужно перепроверить.
- В режиме «колонки» после клика по файлу выделение 100–250 мс читается как пустое, пока Finder строит колонку предпросмотра. Пробел, нажатый в этот момент, откроет стандартный Quick Look.
- Перехват работает только в Finder. В других приложениях (диалоги открытия файлов, сторонние файловые менеджеры) по-прежнему открывается стандартный Quick Look.

## Открытые вопросы

- **Структура Accessibility Finder на macOS 14–26.** Прототип запускался только на macOS 27.

### Принятые решения

- **Не-изображения** определяются заранее по кэшу `AXObserver` и пропускаются в стандартный Quick Look. Подтверждено прототипом.
- **Apple Events не используются**, разрешение «Автоматизация → Finder» не нужно: Accessibility отдаёт полные пути, а Apple Events в 20–30 раз медленнее и в галерее и на сетевых дисках иногда возвращают неверное выделение.
- **Короткое пустое выделение в колонках** принимается как ограничение: исправление вернуло бы асинхронную логику. Отвергнуты: своя `QLPreviewPanel` (это уже не родной Quick Look) и ресинтез Пробела (задержка и риск гонок).
- **Несколько выделенных файлов:** листаются только выделенные изображения.
- **Сортировка:** всегда по имени. Повторение сортировки окна Finder — в планах.
- **Минимальная версия macOS:** 14 Sonoma.
- **Формат проекта:** Xcode-проект.
