# Ementium

**Ementium** — минималистичный просмотрщик изображений для macOS, который заменяет стандартный Quick Look для картинок. Выделите изображение в Finder, нажмите **Пробел**, и оно откроется на весь экран поверх затемнённого фона. Стрелками листаются остальные изображения в той же папке, **Esc** закрывает просмотр.

Интерфейса почти нет: нет панелей, кнопок и Dock-иконки. Есть только окно настроек.

## Идея

Встроенный Quick Look удобен, но для просмотра фотографий у него есть недостатки: окно не занимает весь экран, вокруг остаются элементы интерфейса, а листать папку можно только при выделении нескольких файлов. Ementium сохраняет привычный жест (Пробел в Finder) и делает следующее:

- открывает изображение сразу на весь экран;
- затемняет всё вокруг, чтобы ничего не отвлекало;
- позволяет листать все изображения каталога, а не только выделенные;
- закрывается одной клавишей.

## Возможности

- Перехват клавиши **Пробел** в Finder, когда выделено изображение.
- Файлы, которые не являются изображениями (PDF, видео, документы и др.), Ementium не трогает: Пробел уходит в Finder, и открывается стандартный Quick Look.
- Полноэкранный показ поверх всех окон с регулируемым уровнем затемнения фона.
- Навигация стрелками в том же порядке, что и в окне Finder: любая сортировка (имя, дата, тип…), группы, «Недавние», результаты поиска, теги. Остальные файлы приложение «не видит» — документы и видео между картинками пропускаются. Выделение в Finder следует за просмотром, как в Quick Look. Если в Finder выделено несколько файлов, листаются только выделенные изображения.
- Предзагрузка соседних изображений, чтобы листание было мгновенным.
- Сведения о снимке (EXIF), пока удерживается `⌥`.
- Память масштаба каждой увеличенной картинки до закрытия просмотра.
- Показ на том мониторе, где находится активное окно Finder (в плане).
- Работа в фоне без иконки в Dock (агентское приложение).
- Автозапуск при входе в систему.
- Окно настроек — единственный элемент интерфейса.

## Управление

| Клавиша                | Действие                                                      |
| ---------------------- | ------------------------------------------------------------- |
| `Пробел` (в Finder)    | Открыть выделенное изображение                                |
| `→` / `↓`              | Следующее изображение — в порядке окна Finder                 |
| `←` / `↑`              | Предыдущее изображение — в порядке окна Finder                |
| `Esc`                  | Закрыть просмотр                                              |
| `Пробел` (в просмотре) | Закрыть просмотр (как в Quick Look, отключается в настройках) |
| `Home` / `End`         | Первое / последнее изображение (план)                         |
| `⌘,` (в просмотре)     | Открыть настройки                                             |
| `⌘Q` (в просмотре)     | Завершить Ementium                                            |
| `+` / `⌘+`             | Увеличить: «вписать» → 50 → 100 → 200 → 400 → 800 %           |
| `-` / `⌘-`             | Уменьшить (не меньше «вписать»)                               |
| `0` / `⌘0`             | Вписать в экран                                               |
| Разведение / сведение двух пальцев | Плавный масштаб в точке между пальцами             |
| Двойное касание двумя пальцами, двойной клик | «Вписать» ↔ 100 % в точке под курсором   |
| Прокрутка двумя пальцами, нажать и тянуть | Двигать увеличенное изображение            |
| Удерживать `⌥`         | Сведения о снимке (через 0,5 с); `⌥` + стрелки листают, сведения остаются |

> **Примечание.** `Esc` закрывает окно просмотра, но не завершает само приложение: процесс Ementium должен работать постоянно, иначе перехват Пробела в Finder перестанет работать. Полностью выйти можно через `⌘Q` в просмотре, окно настроек или пункт в строке меню (если он включён).

> **Как открыть настройки.** Клавиши получает только активное приложение, а Ementium активен лишь пока открыт просмотр. Поэтому `⌘,` работает только в просмотре: в Finder это сочетание открывает настройки самого Finder. Без открытого просмотра настройки открываются повторным запуском Ementium (из «Программ», Spotlight или Launchpad) или через иконку в строке меню, если она включена.

## Поддерживаемые форматы

Декодирование выполняет системный фреймворк **ImageIO** (RAW — **CoreImage**, SVG — **AppKit**), поэтому набор форматов зависит от версии macOS.

| Формат | Расширения | Примечание |
|---|---|---|
| JPEG | `.jpg`, `.jpeg` | |
| PNG | `.png` | |
| HEIF / HEIC | `.heic`, `.heif` | |
| TIFF | `.tif`, `.tiff` | |
| GIF | `.gif` | Анимация — в плане |
| BMP | `.bmp` | |
| WebP | `.webp` | Только чтение |
| AVIF | `.avif` | |
| JPEG XL | `.jxl` | |
| PSD | `.psd` | Отображается сведённое изображение |
| RAW | `.cr2`, `.cr3`, `.nef`, `.arw`, `.dng` и др. | Через встроенную поддержку RAW в macOS (`CIRAWFilter`) |
| SVG | `.svg` | Через `NSImage`: всегда вписан в экран, при увеличении перерисовывается чётко |

Перед выпуском список нужно проверить на минимальной поддерживаемой версии (macOS 14), особенно AVIF и JPEG XL. Определять тип файла следует через `UTType` (соответствие `public.image`), а не по расширению.

## Как это работает

Приложение состоит из нескольких независимых компонентов.

```
┌──────────┐   уведомления AX   ┌──────────────────────────────┐
│  Finder  │───────────────────▶│ FinderBridge                 │
│          │◀───────────────────│ кэш фокуса и выделения;      │
└────┬─────┘  стрелки листания  │ листание вслед за Finder     │
     │                          └──────┬────────────────▲──────┘
     │ клавиши             чтение кэша │          шаги  │
     ▼                                 ▼                │
┌───────────────────────────────────────────────────────┴──────┐
│ KeyInterceptor                                               │
│ Пробел в Finder — открыть; в просмотре — разбор всех клавиш  │
└──────────────────────────────┬───────────────────────────────┘
                               │ файл или выделенные файлы
                               ▼
┌───────────────┐  картинка  ┌─────────────────────────────────┐
│ ViewerWindow  │◀───────────│ FinderBridge: что выделил Finder│
│ (оверлей)     │◀───────────│ ImageDirectory: свой список     │
└───────────────┘            └─────────────────────────────────┘
```

Главный принцип: callback перехвата не обращается к другим процессам. Всё, что нужно знать о Finder для решения «поглотить или пропустить», `FinderBridge` вычисляет заранее и держит в кэше.

### 1. `KeyInterceptor` — перехват клавиатуры

- Использует **`CGEventTap`** на уровне сессии и слушает события `keyDown`.
- Поглощает Пробел, только если выполнены все условия:
  - активное приложение — Finder (`com.apple.finder`);
  - нажат Пробел без модификаторов;
  - по кэшу `FinderBridge` фокус не в текстовом поле (переименование файла, поиск, адресная строка);
  - по кэшу `FinderBridge` среди выделенных файлов есть изображение.
- Если условия выполнены, событие поглощается (callback возвращает `nil`), и Quick Look не открывается. Иначе событие пропускается в Finder без изменений, и для PDF, видео и прочих файлов открывается стандартный Quick Look.
- Если кэш не готов или не актуален (Finder только что запущен, режим отображения не поддерживается), Пробел тоже пропускается. Хуже, чем без Ementium, в этом случае не будет.
- Callback должен работать очень быстро: если он задерживается, система отключает tap (`kCGEventTapDisabledByTimeout`). Поэтому внутри callback нет Accessibility-запросов к Finder, только чтение кэша. Tap после отключения повторно включается.

### 2. `FinderBridge` — состояние Finder

- Подписывается через **`AXObserver`** на элемент приложения Finder: уведомления `AXFocusedUIElementChanged`, `AXSelectedRowsChanged`, `AXSelectedChildrenChanged`. Опроса нет: код выполняется только при событиях в Finder.
- По уведомлению обновляет кэш: в текстовом ли поле фокус (роль `AXTextField` / `AXTextArea` и изменяемое `AXValue`), какие файлы выделены и есть ли среди них изображения.
- Выделение читается так: `AXFocusedUIElement` приложения → `AXSelectedRows` (список) или `AXSelectedChildren` (значки, колонки, галерея, рабочий стол) → полный путь из `AXURL` у элемента выделения или его потомка.
- Обновление выполняется с небольшой задержкой (~50 мс) после того, как выделение перестало меняться. Так при быстром пролистывании списка стрелкой Finder не засыпается запросами.
- Тип файла определяется через `UTType` по URL (`contentTypeKey`), а не по собственному списку расширений.
- Apple Events не используются: Accessibility отдаёт полные пути быстрее и надёжнее.
- Работоспособность подтверждена прототипом [FinderAXProbe](Prototypes/FinderAXProbe/README.md) на macOS 27: все режимы отображения, рабочий стол, результаты поиска, iCloud Drive, сетевой диск. Обновление кэша занимает около 2 мс, но при занятом Finder доходит до 300 мс.
- Пока открыт просмотр в режиме «следовать за Finder», мост ещё и листает: отправляет Finder стрелки и сообщает просмотру, какую картинку тот выделил (см. [Листание вслед за Finder](#листание-вслед-за-finder)). Задержки 50 мс в этом режиме нет — иначе при зажатой стрелке картинка застыла бы до отпускания.

### 3. `ImageDirectory` — свой список (несколько файлов и `open -a`)

Нужен там, где следовать за Finder нельзя: при нескольких выделенных файлах (стрелка в Finder сбросила бы выделение) и при открытии через `open -a` / «Открыть в программе».
- Несколько файлов — только выделенные изображения, как в Quick Look; один файл (`open -a`) — все изображения его каталога.
- Сортировка по имени: `localizedStandardCompare` (естественная, как в Finder: «file2» перед «file10»).
- Картинка показывается сразу, а список строится в фоне; стрелки, нажатые до его готовности, не теряются.

### Листание вслед за Finder

Если Пробелом открыт один файл, Ementium не строит свой список, а **листает сам Finder**: стрелка уходит в Finder, Finder двигает выделение в своём порядке, а просмотр показывает выделенную картинку. Поэтому порядок всегда совпадает с окном — любая сортировка, группы, «Недавние», поиск, теги, — а после закрытия в Finder выделена последняя просмотренная картинка. Подход проверен прототипом [FinderFollowProbe](Prototypes/FinderFollowProbe/README.md).

- **Клавиатура остаётся у Finder.** Панель просмотра её не берёт; все нажатия разбирает перехват: стрелки уходят в Finder (напрямую процессу, `postToPid`), Esc и Пробел закрывают, `⌘Q` завершает. Системные сочетания — по списку из настроек пользователя (`com.apple.symbolichotkeys`, с учётом переназначенных): смена языка и скриншоты просмотр не закрывают; Spotlight, Mission Control, рабочие столы, `⌘Tab` — закрывают. Любое другое «модификатор + Пробел» (Alfred, Raycast) — тоже закрывает. Всё остальное глотается: за непрозрачным оверлеем Finder не должен невидимо переименовать, удалить (`⌥⌘⌫`) или переместить файл.
- **Стрелки по видам.** «Список» и «колонки» — ↑↓; «галерея» — ←→; «значки» — последовательно, как в списке: путь к следующему файлу прокладывается по сетке значков (вниз — сначала по ряду, вверх — сначала вверх: → в Finder не переносится на новую строку). Рабочий стол — по сетке, как в Finder: значки там расставлены вручную.
- **Документы и видео пропускаются прыжком.** На нажатие Ementium заглядывает вперёд по элементам окна, находит ближайшую картинку и отправляет Finder нужное число стрелок разом (41 документ — около 0,8 с в «колонках», самом медленном виде). Пока пачка в полёте, следующее нажатие ждёт показа картинки — иначе при зажатой стрелке вторая пачка перелетела бы цель.
- **Край.** Впереди картинок нет — просмотр стоит на месте, в Finder ничего не отправляется (в «значках» слепая → увела бы выделение на значок в ряду выше). В «значках» и «галерее» Finder создаёт элементы лениво, только рядом с экраном: если среди подгруженных картинки нет — прыжок на последний подгруженный, Finder подгружает следующие, поиск повторяется.
- **Если заглянуть нельзя** (группы в «значках») — пошаговый пропуск с ожиданием ответа Finder; край ловится таймаутом, и если за последней картинкой остались только документы, выделение возвращается на картинку.
- **Индикатор ожидания** — если поиск картинки или декодирование дольше 0,3 с.
- Логика листания — чистый автомат `FinderNavigation` (покрыт тестами), отправка клавиш и чтение AX — в `FinderBridge`.

### 4. `ImageLoader` и `ImageCache` — загрузка и предзагрузка

- `ImageLoader` декодирует под размер экрана через `CGImageSourceCreateThumbnailAtIndex`, а не загружает оригинал целиком, с учётом EXIF-ориентации (`kCGImageSourceCreateThumbnailWithTransform`). RAW — через `CIRAWFilter` со своим контекстом CoreImage без кэша промежуточных результатов: через ImageIO тот же RAW раздувал память до 2,6 ГБ и оставлял ~400 МБ в системных кэшах. SVG — через `NSImage` (ImageIO его не рисует). Файл iCloud без локальной копии сначала скачивается (с индикатором).
- `ImageCache` держит текущую картинку и соседей — 2 вперёд, 1 назад (`PrefetchWindow`, покрыт тестами). Текущая грузится сразу, соседи — по одной и только после неё; недогруженная прежняя при листании отменяется; соседи из iCloud не скачиваются, битый сосед не повторяется; изменённый файл перечитывается (дата проверяется в фоне). После закрытия просмотра всё освобождается.
- Соседи в режиме «свой список» — из `ImageDirectory`; в режиме «следовать» — от `FinderBridge`: через 0,15 с после остановки листания он читает элементы окна Finder в порядке окна, любая стрелка прерывает чтение.
- Оригинал в полном разрешении (увеличение) не кэшируется — живёт, пока картинка на экране.
- Ошибки декодирования пишутся в лог с расширением, типом, размером, шагом и статусом iCloud; имя файла скрыто. В лог же — «Показ: из кэша / декодирование» для проверки предзагрузки.

### Сведения о снимке

- Удерживаешь только `⌥` 0,5 с — карточка в углу (угол — в настройках): имя файла, дата съёмки (иначе дата изменения), формат и размер, камера и объектив, фокусное, диафрагма, выдержка, ISO, поправка экспозиции, вспышка, координаты цифрами. Нет поля — нет строки.
- Нажата клавиша или добавлен модификатор за эти 0,5 с — показа не будет до отпускания `⌥` (на `⌥⌘Пробел` ничего не мелькает). `⌥` + стрелки листают, карточка обновляется.
- Автомат удержания — чистый `InfoHoldTracker`, разбор свойств ImageIO — чистый `ImageMetadata` (оба покрыты тестами). Свойства читаются без декодирования картинки.
- В режиме «следовать» модификаторы видит только перехват: событие изменения модификаторов он всегда пропускает дальше (проглоченное «залепило» бы модификатор у системы), а просмотру отдаёт копию.

### 5. `ViewerWindow` — окно просмотра

- Безрамочное `NSPanel` / `NSWindow` на весь экран (`styleMask: .borderless`), уровень выше обычных окон.
- Фон — чёрный с настраиваемой прозрачностью, изображение по центру: большие вписываются в экран, маленькие показываются в естественном размере и не растягиваются.
- Естественный размер: 1 пиксель = 1 пункт экрана. Исключение — Retina-снимки с 144 и 216 dpi (скриншоты): у них 2 и 3 пикселя на пункт, чтобы скриншот окна был размером с само окно. Остальной DPI (240, 300 у экспорта и сканов) игнорируется.
- Плавное появление и исчезновение (fade).
- Окно — панель, которая не активирует приложение (как Spotlight). В режиме «свой список» она получает клавиатуру и при закрытии возвращает фокус приложению, из которого открыли просмотр; в режиме «следовать за Finder» клавиатуру не берёт вовсе (см. выше).
- Если фокус ушёл в другое приложение (⌘Tab, Spotlight, уведомление), просмотр закрывается сам — иначе оверлей висел бы поверх всего без возможности закрыть его клавишей. Клик по фону просмотр не закрывает.
- Пока открыт просмотр, все ⌘-сочетания, кроме описанных в «Управлении» и системных, поглощаются: строки меню у агентского приложения нет.
- Реализация на **AppKit**, так как нужен точный контроль над уровнем окна, фокусом и обработкой клавиш.

### Масштаб

- Геометрия — чистая модель `ZoomModel` (покрыта тестами): «вписать» (большие картинки целиком, маленькие — 100 %, без растягивания), уровни 50/100/200/400/800 %, масштаб в точке (точка под курсором остаётся на месте), сдвиг с ограничением краёв.
- 100 % — естественный размер, как «Реальный размер» в Просмотре. На Retina «пиксель в пиксель» — 50 %.
- При листании новая картинка открывается во «вписать». Масштаб и место картинки, которую увеличивали, запоминаются до закрытия просмотра: вернулся к ней — она такая же, как была (настройка «Запоминать масштаб каждой картинки», по умолчанию включена; выключена — всё всегда во «вписать»). Переноса масштаба с одной картинки на следующую нет: вместе с памятью по файлам он делал масштаб следующей картинки непредсказуемым. Плашка с масштабом — на секунду.
- **Жесты масштаба macOS отдаёт активному приложению** — обычно Finder, а не панели просмотра под курсором (прокрутка и клики при этом приходят панели). Поэтому сведение пальцев и двойное касание забирает перехват: все жесты трекпада приходят в него одним системным типом 29, а вид жеста виден после преобразования в `NSEvent` (выяснено диагностикой).
- **Детали при увеличении:** картинка декодируется под экран; при увеличении сверх этого в фоне декодируется оригинал (до ~100 Мп, ~400 МБ в памяти) — пока он готовится, видна текущая картинка и индикатор.
- **RAW:** сначала встроенное превью (~10 мс), сам RAW под экран (0,15–0,5 с через `CIRAWFilter`) подменяет его в фоне. У Nikon встроенное превью полноразмерное — второе декодирование не нужно. Замеры — [RawProbe](Prototypes/RawProbe/README.md).

### 6. `Settings` — окно настроек

- Интерфейс на **SwiftUI** (`SettingsView`, одна страница с разделами), окно — обычное `NSWindow` с `NSHostingController` (`SettingsWindowController`). Не сцена `Settings`: у агентского приложения открыть её из кода на macOS 14+ можно только недокументированным вызовом.
- Размер окна задан явно и не подстраивается под содержимое: прокручиваемая `Form` с переносом текста и окно, подгоняющее высоту под неё, раскачивали друг друга бесконечным пересчётом констрейнтов, и AppKit ронял приложение. Не влезшее прокручивается, окно можно растянуть по высоте.
- Хранение — `UserDefaults`: окно пишет через `@AppStorage`, остальной код читает снимок `ViewerPreferences`. Ключи и значения по умолчанию — в одном месте, `Preferences`. Окно просмотра берёт настройки при каждом открытии.
- Перехват и иконка в строке меню применяются сразу — по `UserDefaults.didChangeNotification`. Это уведомление приходит на том потоке, где поменяли `UserDefaults`: системный декодер RAW регистрирует свои значения по умолчанию на фоновом. Поэтому обработчик сначала переходит на главный поток.

### Жизненный цикл приложения

- `LSUIElement = YES` в `Info.plist`: нет иконки в Dock и главного меню.
- Автозапуск через `SMAppService.mainApp` (ServiceManagement): включается при первом запуске, дальше — переключатель в настройках. Если macOS ждёт подтверждения в «Объектах входа», в настройках есть кнопка туда.
- Нет «Универсального доступа» (первый запуск или доступ отозвали) — открывается окно настроек с объяснением и кнопкой «Разрешить», системный диалог — только по ней. Доступ проверяется раз в секунду, перехват включается сам, без перезапуска.
- Под тестами Xcode (`XCTestConfigurationFilePath`) приложение-хозяин ничего не запускает: ни перехвата, ни автозапуска, ни окон.
- Повторный запуск уже работающего Ementium открывает окно настроек (`applicationShouldHandleReopen`).

## Системные разрешения

Без этих разрешений перехват работать не будет. Приложение должно проверять их при запуске и показывать понятную инструкцию.

| Разрешение | Зачем | Как проверить |
|---|---|---|
| **Универсальный доступ** (Accessibility) | Создание `CGEventTap`, поглощение событий, `AXObserver` для отслеживания фокуса и выделения в Finder | `AXIsProcessTrustedWithOptions` |
| **Мониторинг ввода** (Input Monitoring) | На macOS 27 для перехвата не понадобился. Запрашивается, только если event tap не создаётся при выданном «Универсальном доступе» | `CGPreflightListenEventAccess` / `CGRequestListenEventAccess` |

Разрешения привязаны к подписи приложения. При разработке с меняющейся подписью macOS может «забыть» выданный доступ, тогда его нужно удалить и выдать заново в **Системные настройки → Конфиденциальность и безопасность**.

## Сборка и запуск

```bash
git clone <url-репозитория>
cd Ementium
open Ementium.xcodeproj
```

1. В Xcode выберите свою команду разработчика: **Signing & Capabilities → Team**. App Sandbox в проекте уже выключен, Hardened Runtime включён.
2. Соберите и запустите схему `Ementium` (`⌘R`). Окон при запуске нет: это агентское приложение без иконки в Dock.
3. Откройте изображение:
   ```bash
   open -a Ementium путь/к/картинке.jpg          # весь каталог
   open -a Ementium a.jpg b.png                  # только эти файлы
   ```
   Того же можно добиться через **Открыть в программе → Ementium** в контекстном меню Finder.
4. Для перехвата Пробела установите приложение скриптом — он собирает Release, кладёт единственную копию в `~/Applications` и запускает её:
   ```bash
   scripts/install.sh            # собрать, установить, запустить
   scripts/install.sh --no-open  # без запуска
   ```
   При первом запуске откроется окно настроек с объяснением: нажмите «Разрешить» и включите Ementium в Системных настройках — перехват заработает сам, без перезапуска.

Из терминала:

```bash
xcodebuild -project Ementium.xcodeproj -scheme Ementium build    # Debug, только текущая архитектура
xcodebuild -project Ementium.xcodeproj -scheme Ementium test     # тесты
xcodebuild -project Ementium.xcodeproj -scheme Ementium -configuration Release \
  -destination 'generic/platform=macOS' build                    # Universal: arm64 + x86_64
```

Для распространения вне Mac App Store приложение нужно подписать сертификатом **Developer ID** и пройти **нотаризацию** (`notarytool`).

## Ограничения

- **Нет App Sandbox, нет Mac App Store.** Глобальный перехват клавиатуры через `CGEventTap` и чтение интерфейса Finder через Accessibility несовместимы с песочницей, а приложения без песочницы нельзя публиковать в Mac App Store. Распространение — через Developer ID и нотаризацию.
- Работа зависит от поведения Finder. Обновления macOS могут изменить структуру Accessibility-элементов Finder. Прототип проверен только на macOS 27, на минимальной версии (macOS 14) её нужно перепроверить.
- В режиме «колонки» после клика по файлу выделение 100–250 мс читается как пустое, пока Finder строит колонку предпросмотра. Пробел, нажатый в этот момент, откроет стандартный Quick Look.
- Курсор «рука» над увеличенной картинкой появляется только в режиме «свой список». В режиме «следовать за Finder» активен Finder, а macOS не даёт фоновому приложению менять курсор (обойти можно только частными API — не используем). Двигать картинку это не мешает.
- Перехват работает только в Finder. В других приложениях (диалоги открытия файлов, сторонние файловые менеджеры) по-прежнему открывается стандартный Quick Look.

## Открытые вопросы

- **Структура Accessibility Finder на macOS 14–26.** Прототип запускался только на macOS 27.
- **Память после просмотра.** После закрытия просмотра Ementium держит ~150–300 МБ (после запуска — ~17 МБ). Это не кэш Ementium (он очищается) и не утечка (от прогона к прогону объём не растёт): трассировка выделений показала глобальный кэш декодированных изображений CoreGraphics, который заполняется внутри ImageIO при уменьшении картинки и при отрисовке SVG. Вне приложения тот же загрузчик возвращает память до ~30 МБ за пару секунд. Решение — декодирование в отдельном процессе (v1.0, см. ниже).
- **Декодирование в XPC-сервисе (v1.0).** Декодеры (ImageIO, RAW через CoreImage, SVG) переезжают в XPC-сервис в песочнице, который запускается по требованию и завершается после закрытия просмотра. Почему это правильнее, чем подбирать обходы внутри процесса:
  - память: кэши и пиковые объёмы декодеров (RAW — до ~1 ГБ на время декодирования) живут и умирают вместе с сервисом, независимо от того, что и как кэширует каждый системный декодер;
  - устойчивость: Ementium работает постоянно и держит перехват клавиш — падение декодера на битом файле уронит только сервис, а просмотр покажет «Не удалось открыть»;
  - безопасность: у основного процесса право «Универсальный доступ» и нет песочницы (несовместима с event tap), а разбор недоверенных форматов — самое рискованное, что он делает. ImageIO уже бывал целью атак через картинки (например, активно эксплуатировавшаяся CVE-2023-41064). Сам Quick Look тоже строит превью вне процесса;
  - настоящая отмена: зависший или ненужный декодер останавливается завершением сервиса, а сейчас отмена задачи не прерывает уже начатое декодирование.

  Что учесть: картинку передавать через IOSurface (без копирования, `CALayer` показывает её напрямую); доступ к файлу из песочницы — через переданный дескриптор; скачивание из iCloud — в основном приложении; холодный запуск сервиса добавит задержку к первой картинке — замерить и при необходимости поднимать сервис заранее, когда в Finder выделена картинка (это уже известно из AX-кэша); сведения EXIF возвращать вместе с картинкой.

### Принятые решения

- **Не-изображения** определяются заранее по кэшу `AXObserver` и пропускаются в стандартный Quick Look. Подтверждено прототипом.
- **Apple Events не используются**, разрешение «Автоматизация → Finder» не нужно: Accessibility отдаёт полные пути, а Apple Events в 20–30 раз медленнее и в галерее и на сетевых дисках иногда возвращают неверное выделение.
- **Короткое пустое выделение в колонках** принимается как ограничение: исправление вернуло бы асинхронную логику. Отвергнуты: своя `QLPreviewPanel` (это уже не родной Quick Look) и ресинтез Пробела (задержка и риск гонок).
- **Несколько выделенных файлов:** листаются только выделенные изображения.
- **Порядок листания:** при открытии Пробелом — порядок окна Finder (Ementium следует за выделением Finder). Угадывание сортировки по видимым файлам (эксперимент удалён) и эвристика заголовка окна для «Недавних» отвергнуты: каждый режим Finder требовал бы своей эмуляции, а сортировку по типу угадать не удалось.
- **«Значки»** листаются последовательно, а не по сетке: сетка неудобна для фото вперемешку с документами.
- **Минимальная версия macOS:** 14 Sonoma.
- **Формат проекта:** Xcode-проект.
